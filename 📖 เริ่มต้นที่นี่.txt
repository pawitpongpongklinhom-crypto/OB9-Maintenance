     ไม่ทับราคาที่กรอกเอง)
   • ② ค่าแรงต่อชั่วโมง ↔ อัตราจริงต่อช่าง: เพิ่มช่อง "ค่าแรง (บาท/ชม.)" ในหน้า Training (ob9_training.html)

   ในชีต "OB9 Work Order Sync — Mae Moh Mine" มีแถวซ้ำสะสมกว่า 4,800 แถว (Spreader A เครื่องเดียวมีถึง
   2,710 แถว ทั้งที่ควรมีแค่ 1 แถวต่อวัน) และพบว่าหมวดชั่วโมงที่บันทึกไว้ของ Spreader A/Tripper A ผิดเป็น
   "Relocate" และ Line Shift A9 ผิดเป็น "Operate" ทั้งที่ควรเป็น "Breakdown" ตามที่ผู้ใช้แจ้ง
   • สาเหตุที่แท้จริง: โค้ดอ้างอิง Google Apps Script (Code.gs) ที่ฝังไว้ในหน้า Dashboard Tab "⚙ เชื่อมต่อ
     Google Sheet" รองรับแค่ 2 ชุดข้อมูล (Work Orders, Spare) มาตั้งแต่ต้น — ไม่เคยมีฟังก์ชันรองรับ
     type=machineStatus/production/inspection เลย ทั้งที่ Client (ob9_dashboard.html, ob9_inspect.html)
     ส่งข้อมูล 3 ชุดนี้ขึ้น Sheet มาตลอด ทำให้โค้ดที่ deploy จริงต้อง append แถวใหม่ต่อท้ายทุกครั้งที่ sync
     แทนที่จะล้างของเก่าก่อนเขียนทับเหมือน Work Orders/Spare ที่ถูกต้องอยู่แล้ว
   • พบสาเหตุร่วมอีกจุด: Google Sheets แปลงข้อความวันที่ "YYYY-MM-DD" เป็น Date object ของเซลล์เองอัตโนมัติ
     พอส่งกลับมาให้ Client กลายเป็น timestamp ("...T17:00:00.000Z") ไม่ตรงกับ string เดิมที่เครื่องบันทึกไว้
     ทำให้ merge หาแถวเดิมไม่เจอ สร้างแถวใหม่ซ้อนไปเรื่อยๆ ทบต้นทุกรอบ sync
   • แก้โดยเขียน Code.gs ใหม่ทั้งหมดให้ครบทั้ง 5 ชุดข้อมูล (Work Orders, Spare, Machine Status, Production,
     Inspection) ทุกชุดใช้กติกาเดียวกัน "ล้างข้อมูลเก่าทั้งหมดก่อน แล้วเขียนชุดใหม่ทับ" และแปลงวันที่กลับเป็น
     YYYY-MM-DD เสมอตอนส่งออก (ฟังก์ชัน _fmtDate_) แก้ปัญหาที่ต้นตอทั้งสองจุด
   • โค้ดใหม่อยู่ในหน้า Dashboard Tab "⚙ เชื่อมต่อ Google Sheet" แล้ว — ต้องคัดลอกไปวางทับใน Apps Script
     Editor (Extensions → Apps Script) แล้ว Deploy → Manage Deployments → New Version ใหม่ 1 ครั้ง ถึงจะมีผล
     จริง (แก้ไฟล์ในเครื่องอย่างเดียวไม่พอ เพราะ Apps Script รันอยู่บนเซิร์ฟเวอร์ Google แยกต่างหาก)
   • หลัง Deploy ใหม่แล้ว กด "🔄 Sync" ในหน้า Dashboard อีก 1 ครั้ง แถวซ้ำที่มีอยู่เดิมในชีท Machine Status
     จะถูกล้างและเขียนทับด้วยข้อมูลที่ deduplicate แล้วให้เองอัตโนมัติ ไม่ต้องลบมือทีละแถว
   • ส่วนหมวดชั่วโมงที่ผิด (Relocate/Operate แทน Breakdown) ต้องแก้โดยเข้า Tab "จอดยาว (ช่วงวันที่)" เลือก
     เครื่อง Spreader A/Tripper A/Line Shift A9 แล้วกรอกใหม่เลือกหมวด "Breakdown" ทับของเดิม — เป็นเรื่อง
     ข้อมูลที่กรอกผิดหมวดตั้งแต่ต้น ไม่ใช่บั๊กของหน้าจอ
   • [อัปเดต] เปิดโปรเจกต์ Apps Script จริงที่ deploy อยู่ (ผ่าน Extensions → Apps Script จาก Sheet ตรง —
     พบว่า Sheet นี้มีโปรเจกต์ผูกอยู่หลายอันจากการเชื่อมต่อซ้ำในอดีต ต้องเช็ค URL deployment ให้ตรงกับที่
     ระบบใช้จริงก่อน) ยืนยันเจอบั๊กตัวจริงในฟังก์ชัน _postMachineStatus เดิม (เพิ่มไว้เมื่อ 18 ก.ค. 69):
     สร้าง index จาก rows[i][0] ที่ Sheets แปลงเป็น Date object อัตโนมัติ แต่ key ขาเข้าจาก Client เป็น
     string "YYYY-MM-DD" เทียบกันไม่ตรงเลยสักครั้ง ทุกแถวเลยตกไปที่ appendRow เสมอ — นี่คือสาเหตุแท้จริง
     ของแถวซ้ำหลักพันแถว วางโค้ดใหม่ทับและ Deploy เป็น Version 6 (23 ก.ค. 69 เวลา 15:31) เรียบร้อยแล้ว
     URL Web App เดิมไม่เปลี่ยน ไม่ต้องแก้ไฟล์ฝั่ง Client ใดๆ เพิ่มเติม — กด "🔄 Sync" ในหน้า Dashboard
     อีกครั้งเดียวเพื่อให้แท็บ Machine Status ที่บวมอยู่ถูกล้างและเขียนทับด้วยข้อมูลสะอาดอัตโนมัติ

✅ 23 ก.ค. 69 (2) — เชื่อมข้อมูล SMU/KWH ระดับอุปกรณ์จาก production-itd.ith.co.th เข้า OB9
   ผู้ใช้ขอให้ลิงก์ข้อมูล SMU และ KWH จากเว็บภายใน production-itd.ith.co.th (ระบบติดตาม SMU/KWH ของ
   สายพานลำเลียง/Spreader/Tripper) เข้ามาที่ OB9 แบบละเอียดระดับอุปกรณ์ย่อย (ไม่ใช่แค่ยอดรวมต่อเครื่อง)
   • มีการยืนยัน mapping จากผู้ใช้: line=A → Spreader A (กลุ่มอุปกรณ์ SPD.A ยกเว้น "Triper Car") + Tripper A
     ("Triper Car") + Line Shift A1.1 (equipment "A1.1") + Line Shift A9 (equipment "A9"); line=B → Spreader B
     (SPD.B) + Tripper B + Line Shift B1.1 (equipment "B1.1"); line=N และข้อมูล CRUSHER ทั้งหมดไม่รวมในระบบนี้
   • เพิ่มชุดข้อมูลที่ 6 ใน Apps Script (type=equipmentSmuKwh) — ชีตใหม่ "Equipment SMU-KWH" เก็บ
     Date/Machine ID/Machine Name/Line/Section/Equipment/SMU/KWH Start/KWH Finish/Water Start/Water
     Finish/Source/Updated At ต่อแถว (1 แถว = 1 อุปกรณ์ย่อย 1 วัน) ใช้กติกาเดียวกัน "ล้างของเก่าก่อนเขียนทับ"
   • ระหว่างทดสอบจริงพบบั๊กเพิ่มอีกจุดใน _fmtDate_ (ฟังก์ชันแปลงวันที่กลับเป็น YYYY-MM-DD) — ใช้
     "instanceof Date" ตรวจสอบแล้วไม่พบ Date object ในบางกรณีจริง ทำให้วันที่หลุดออกมาเป็น ISO timestamp
     เต็ม แก้เป็น Object.prototype.toString.call(v)==='[object Date]' แทน (เชื่อถือได้กว่า) — แก้จุดนี้
     มีผลดีกับ Machine Status/Production/Inspection ที่ใช้ _fmtDate_ ร่วมกันด้วย ไม่ใช่แค่ชุดใหม่
   • Deploy จริงแล้วเป็น Version 8 (23 ก.ค. 69 เวลา 23:33) — URL Web App เดิมไม่เปลี่ยน
   • ทดสอบ pull ข้อมูลจริงจาก production-itd.ith.co.th (Line A วันที่ 23 ก.ค. 69) แล้ว push เข้าชีตสำเร็จ
     ยืนยันด้วยการ GET กลับมาดู 12 รายการ วันที่ถูกต้องเป็น "2026-07-23" (ไม่ใช่ timestamp) แล้ว
   • ⚠️ หมายเหตุสำคัญ: production-itd.ith.co.th ใช้ session cookie login ไม่ใช่ API key — การดึงข้อมูลนี้
     ต้องทำผ่านเบราว์เซอร์ที่ login ค้างอยู่แล้วเท่านั้น (ทำโดย Claude ผ่านคำสั่ง หรือทำเป็น scheduled task)
     ไม่สามารถกดปุ่มจากไฟล์ ob9_dashboard.html (file://) ได้ตรงๆ เพราะติด CORS/ไม่มี cookie ข้าม origin
   • ⚠️ พบว่า endpoint /api/admin/smu-kwh?...&line=... (หน้า operation/smu-kwh) ตอบช้า/ค้างบ่อยเมื่อยิงซ้ำ
     เร็วๆ — ใช้หน้า /smu-kwh (สรุปเทียบ 3 line พร้อมกัน) แทนเพราะโหลดเร็ว/เสถียรกว่า แต่หน้านั้นมีแค่ SMU
     ไม่มี KWH — ค่า KWH ยังไม่ได้ดึงจริงในรอบนี้ รอ endpoint เดิมเสถียรขึ้น หรือให้ผู้ใช้ช่วยเช็คกับ IT
   • ดูข้อมูลที่ซิงก์แล้วได้ที่ปุ่ม ⏱ SMU → tab "🏭 Production ITD" ในหน้า Dashboard

   DEFAULT_SYNC_URL/TOKEN ฝังไว้อยู่แล้ว (เพราะเหตุนี้ 2 หน้านั้นถึงใช้งานได้จากทุกเครื่องมาตลอด) ค่า
   'ob9_sync_settings' จะถูกตั้งก็ต่อเมื่อ Admin เปิดหน้า Dashboard มากรอก URL/Token เองเท่านั้น — มือถือ
   ของพนักงานทั่วไปที่ไม่เคยเปิด Dashboard มาก่อนเลย (คือแทบทุกคน) จึงไม่มีทาง pull รายชื่อพนักงานจาก Sheet
   ได้เลยตั้งแต่ต้น ไม่ว่าจะแก้ normId/normName/honorific/target=admin/cache ไปกี่รอบก็ตาม เพราะ employees
   array ว่างเปล่าตลอด แก้โดยเพิ่ม DEFAULT_SYNC_URL/TOKEN แบบเดียวกับ WO form ในทั้ง 2 ไฟล์ และตั้งค่า
   อัตโนมัติลง localStorage ให้เองถ้าเครื่องนั้นยังไม่มี — ทดสอบจริงด้วยการเคลียร์ localStorage ทั้งหมดจำลอง
   มือถือเครื่องใหม่ แล้ว login ด้วยรหัสพนักงานจริง ผ่านสำเร็จ ยืนยันว่าเป็นสาเหตุตัวจริง

   ระหว่างแก้ไขจุดนี้ยังพบว่าตัวเองทำโค้ดพังซ้อนอีก 2 ชั้นโดยไม่ตั้งใจ (แก้ไขและทดสอบจนผ่านหมดแล้ว):
   1. คอมเมนต์ meta cache-control ที่เพิ่มไว้ในข้อ (2) ปิดท้ายด้วย "*/" (syntax ของ CSS) แทนที่จะเป็น "-->"
      (syntax ของ HTML comment) — คอมเมนต์เลยไม่เคยถูกปิด เบราว์เซอร์กลืน <title>, <style> ทั้งก้อน, ไปจนถึง
      ต้น <body> (โลโก้/ช่องชื่อพนักงาน) เข้าไปเป็นคอมเมนต์เดียวกันหมด จนกว่าจะเจอ "-->" ตัวถัดไปในไฟล์ (ที่
      <datalist> ด้านล่าง) ทำให้หน้า login เพี้ยนไม่มี CSS/โลโก้/ช่องชื่อเลย เหลือแค่ช่องรหัสพนักงานอย่างเดียว
      — ผู้ใช้ส่งภาพมาให้ดู เข้าใจว่าเป็น "โหมดอ่าน" ของเบราว์เซอร์ แต่จริงๆ คือบั๊กนี้
   2. แก้ข้อ 1 รอบแรกโดยเขียนคอมเมนต์อธิบายบั๊กเพิ่ม แต่ดันพิมพ์ข้อความ "-->" (ในเครื่องหมายคำพูด อธิบาย
      syntax) อยู่ภายในคอมเมนต์เอง ทำให้คอมเมนต์ปิดก่อนกำหนดอีกรอบ (HTML ไม่สนใจเครื่องหมายคำพูด มองแค่ตัว
      อักษร "-->" ดิบๆ) เกิดปัญหาเดิมซ้ำอีกรอบ แก้โดยตัดข้อความอธิบายยาวๆ ออก เขียนสั้นๆ แทนไม่ให้มีคำว่า
      "-->" อยู่ในคอมเมนต์เลย
   ทั้งหมดนี้ทดสอบแล้วด้วยการ syntax-check + เคลียร์ localStorage จำลองเครื่องใหม่ + login จริงจนสำเร็จ
   ก่อน push เวอร์ชันสุดท้ายขึ้น GitHub (commit bb17539)
